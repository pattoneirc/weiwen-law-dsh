## 一、白话版（这节没有公式，可以先只看这里）

**原来的毛病**：我把「规则」当成一本**写好的字典**，然后到处找某一页上写着「这个行业允许错几次」。找不到就记一笔欠账。可字典本来就不该由我们编——**该去查**。查是动作，不是填空。

**R 现在是什么**：一个**动作**，叫「去查」。查什么：这个事属于哪个行业 → 那个行业的标准怎么写 → 标准给的是哪一类数 → 谁查的、哪一版。查完拿回来的是一张**标准清单**（这就是 S）。所以 R 和 S 是**一回事的两面**：R 是去拿，S 是拿到的东西。公式里 `R × S` 也就讲通了——它不是两个不相干的数相乘。

**H 现在是什么**：一个**看的人**。他看完标准（S），再看完实际情况（D），然后**做一个选择**：这次是**更死守标准**，还是**多为实际让一点**。这个选择就是「H 的位置」。所以 H 不是量出来的，是**选出来的**——AI 不能替人做这个选择，只能建议。

**张力是什么（你问的那个）**：「标准要求的样子」和「实际情况的样子」之间**差多远**。就这么简单。

- 差得小 → 稍微让一点就行，不用费什么劲
- 差得大 → 要么狠心守标准，要么大幅让步，中间那段是要花力气的
- **一点不差 → 根本不需要"有人来判断"**。照做就完了。这就是「张力为零」——注意它**不是"通过"，是"这件事用不着能动性"**

最后这个我觉得挺重要：**没有矛盾的地方，就不需要判断；需要判断的地方，一定有矛盾。** 反过来说，如果一套流程里所有事都"没有张力"，那这套流程里的"人"其实是多余的。

**但算法有两种，因为行业给的东西不一样**：

- 有些行业给一个**数**（医疗输液泵流量 ±5%）→ 那就能直接算「差了几个百分点 ÷ 允许几个百分点」
- 有些行业只给**要求**（必须做气泡检测、必须断电维持 30 分钟），不给数 → 那就**列表格对**：要求做的，实际做了没有，没做的是哪几条
- 第二种**不能硬凑成一个数**。硬凑就是编。这跟"清单写不完就当成判据"是同一个病。

## 二、R ＝ 可执行动作

| 项 | 内容 |
|---|---|
| verb | `resolve_domain`（查域） |
| 步骤 | ① 定位规则族 ② 查标准正文（标准号＋条款＋数值＋单位＋版本） ③ **判量纲**（率／物理容差／有序等级／标准合法地不给数）④ 记 provenance |
| 产出 | **S（标准清单）—— 不是 R 的数值** |
| 禁令 | 🔴 把 R 定死成常数 ＝ 把动作当成结果 |

### `rCapacity.mjs` 那张表的身份变了（代码不动，定位改）

它现在是 **R 动作的历史产物缓存（S）**，不是 R 本身。

这一改，顺带解决两笔旧账：

1. **表里没有的域 ≠ 缺口**，是「还没查」。动作可执行，随时能补。
2. 上轮我把「R₀ 取哪个数」当成核心难题 —— 那是在一个错误的形态里找东西。**R 不产出数，R 产出清单。** 只有当 step③ 判为「率」时，才可能进一步换算出事件阈值（那才是 docs/26 那套公式的适用处）。

### 缓存未命中怎么办（「可执行」要有下一步）

- **触发**：要处理的域不在缓存里
- **做**：由执行者现场执行四步，查完**写回缓存**（带 provenance）
- 🔴 **不许把「缓存里没有」当成「判不出」** —— 那不是 L2/L3，是**该执行动作而没执行**
- 拿不到（无网络/无权限）⇒ 如实报「查证未完成」，落 review；**不得默认放行，也不得拍数**

| 项 | 内容 |
|---|---|

## 四、张力 L：三档，按「这个域给了什么」路由

| 档 | 前提 | 算法 | 输出 | 带数吗 |
|---|---|---|---|---|
| **A** | 有容差（如 ±5%） | `L = |dev| / tol` | 无量纲，单位＝「几个容差」；判 `within`／`at`／`over` | ✅ |
| **B** | 只有条款/动作 | `gap = required − allowed` | **缺口清单**（缺哪几条） | ❌ 永不 |
| **C** | 都拿不到 | —— | `unknown` | ❌ |

### 为什么 B 档不给数（这条最要紧）

集合差**没有大小**。如果硬给一个数（比如缺口条数），那么「缺 1 条致命项」和「缺 1 条无关项」会算成一样 —— 这就是拿**可数的**冒充**可比的**。缺口条数是枚举量，不是度量。

所以 B 档只回答两件：**缺口是不是空的**、**缺在哪几条**。并且 **B 档不参与位置判定**（见第五节）。

### 为什么不用「只测打、不测正常」那种坑

`tol = 0` 时**不能**算成 L = 0。L = 0 的意思是「完全一致、无张力」；tol = 0 的意思是「标准本身没给容差」——**两件完全不同的事**，前者是结论，后者是缺数据。代码里显式分开（`unknown` + `missing: 'tol 必须 > 0'`）。

## 五、位置：`0 < H/(S↔D) < R` 到底怎么算

> 🔴 **本节第 104 行「R ＝ 域允许的比例上限（必须在 (0,1)）」已撤回**（安 2026-10-20 12:3x 亲裁：R 无上限，R=100 只是刻度）。
> 正确读法与三层区分见 **docs/30**。下文保留原文作为撤回留痕，**判据以 docs/30 为准**。
> 保留下来的部分：`0 < H < L·读数/刻度` 这个展开式本身没错，错的是「R 是界」这个身份。

把这个式子直接展开：

```
0 < H/L < R     ⇒     **0 < H < R·L**（R 按刻度读时：0 < H < L·R/刻度）
```

- **H ＝ 绝对余量**（单位同 L：几个容差）
- ~~**R ＝ 域允许的比例上限**（必须在 (0,1)，否则动力臂可为 0 或负）~~ ← **撤回**
- **R·L ＝ 允许的最大余量**（刻度 100 时即 L 本身）

三种结果：

| 情形 | 状态 | 含义 |
|---|---|---|
| `H ≤ 0` | `off_low` | 贴死标准端 ⇒ 一点不让 ⇒ 能动性归零 |
| `H ≥ R·L` | `off_high` | 让得太多 ⇒ 动力臂不足 ⇒ 杠杆失效（脱域） |
| `0 < H < R·L` | `on_rail` | 在轨内 |
| `L = 0` | `zero_tension` | 可行域收缩为空 ⇒ **H 无处着力**（＝照做就行，不需要判断） |

⚠️ 注意 `zero_tension` 我上轮写成「违反下界 0<」，措辞不准。准确说法是**可行域退化为空集**——不是"越界"，是"没有位置可选"。

## 六、🔴 实跑抓到的真错：公式里有个 L，代码里没有它

第一版 `slidePos` 我把输入当成「占比」直接比，于是 **L 完全没参与计算**。实跑一看就露：

```
偏差  7% ⇒ L=1.40 (over) ⇒ 位置 on_rail
偏差 -12% ⇒ L=2.40 (over) ⇒ 位置 on_rail    ← 张力差 71%，位置一模一样
```

**这就是「公式里明明有这一项，代码里当它不存在」。** 它跟「写了 ≠ 生效」是同一族，只是藏得更深：不是没写，是**写了但没接到判据上**。

修完（`H < R·L`）之后同一组数据才分开：张力小的时候，同样的余量就越界了。

为此加了两条锁：

- **⑱** 同一个余量、换不同张力 ⇒ 位置**必须不同**；上界必须等于 `R·L`（不是 `R`）
- **⑲** 张力越大 ⇒ `R·L` 必须越大（解析 `boundExpr` 后比较，单调性）

> 教训一句话：**能算出来的东西，必须实跑一次；只看代码读不出「哪一项没接上」。**

## 七、上一轮有一条 guard 锁得过宽，这轮修正

上轮我写：**「禁止把 `S↔D` 求值成一个数」**。这轮你问「张力怎么算」，说明**这一段是有可求量的**。

精细区分：

- ❌ 禁的是：把 `↔` 当**运算符**（`S ⊕ D` 这种写法）
- ✅ 放行的是：求**区间长度** —— 那是**区间的属性**，不是 `↔` 的运算结果

**为防一个类别错，把正解一起锁掉 ＝ 过宽。过宽与过窄同罪：都让判据失去分辨力。**

自我修正已登记在 `M_CONSTRAINT.selfCorrection`（含原话、现话、病名、谁纠正的），不删——删了就看不出我错过什么。
