# 42 · 误拦与误放是同一个病：声明通道（层二）＋ 坐标外化（层一）

> 2026-10-28 · 0.2.9 · 作者裁定「拦和审是两件事」之后的第二次落码。
> 上一版（docs/41）立了两根轴；这一版处理轴底下那个具体病灶。

## 一、起于一句归纳，验出三处不合

安的原话：

> 「唯稳律拦的基本都是**外部对内部的越界**，内部自己几乎都是正常运行。像小D：开着唯稳律没感觉，只有想往天堂推的时候才出面拦一下。」

**方向对，而且它给出了定性：唯稳律是边界守卫，不是行为审查官。** 与「内 H 不可侵／外 H 必须可审」同构 —— 内部不动，出口才查。

但拿 14 格实测验，三处不合：

| 组 | 应然 | 实测（0.2.8） |
|---|---|---|
| 内部（域内·可逆·无对外落点） | 7/7 放行 | **3/7** |
| 外部（越界／凭据／对外通道） | 7/7 拦 | **5/7** |

误拦的三格：`glob` / `grep` / `list_dir` —— 全是正常只读动作。
误放的两格：`fetch {url}`（对外通道被归成 `file-read` ⇒ risk=low ⇒ allow）、`write_file {path:'https://…'}`（只读动词，不读落点）。

**三处不是一个问题，是一个病的三个症状：判据读的是「词形」，不读「落点」。**

- 名字里没有动作词 ⇒ 没有入口 ⇒ 一律交还（**误拦**）
- 名字里有动作词 ⇒ 只看动词、不看对象 ⇒ 放行（**误放**）
- 名字里既有动作词、参数又自带命令行 ⇒ 落点看得见 ⇒ 判对（`bash curl` 一支）

⚠️ 这解释了一个长期怪现象：**越加判据，误拦越多。** 新判据照旧长在"已经能看见的类别"上（file-read / file-write / file-delete），看不见的那几类一直在旁边绕过去。**先结构后枚举，说的就是这个。**

## 二、为什么不能靠参数形态补（这条被回归测试打回过一次）

第一版把「不可能是什么」写成了排除法：无内容载体 ⇒ 写不了；无对外落点 ⇒ 传不出；无命令槽 ⇒ 跑不了 ⇒ 只剩读。

当场被 `fail-closed-gate` 问句③ 打回：`tool_42 {path:'/'}` 变成 **allow**。

病灶：**删除不需要内容，只需要路径。** 排除法漏了 delete 这一格。

再往下一层，是更硬的结论：

> `glob {pattern:'*.tmp'}` 与 `delete_matching {pattern:'*.tmp'}` **参数形态完全相同**。

一个是搜索，一个是按模式批量删。任何「有 pattern ⇒ 读」的规则都会被后者打破。**形态这一层是一对多的，它不能当主证，只能当旁证。**

⇒ 形态归属改名为 `arg-form`，职责收窄为**交叉核验**，不再单独定层。

## 三、层二：可信声明通道

### 判据
**知道答案的那一方直接说。** 宿主注册工具时本来就知道 `glob` 是只读的 —— 让引擎从名字里重新猜，是把已知信息丢掉再猜回来。

### 接口
```js
engine.declareTool('glob', { verb: 'read', reversible: true, note: '通配符搜索' })
new WeiwenLawEngine({ toolDeclarations: { glob: { verb: 'read' } } })
```
`verb ∈ {read, write, delete, exec, send}` —— 与框架既有动作类别同一套，不另开词表。
归因 `method` 记为 `'declared'`，**来源可追溯**（能分清"它是判出来的"还是"它是被告知的"）。

### 🔴 三把锁

1. **不许从 `call` 里读。** 声明只能由构造函数或 `declareTool()` 写入。
   理由与「言不进池」同源：**被审方自述不得作为授权来源**。若声明写在工具参数里，agent 自带 `{'verb':'read'}` 即自我授权。
2. **声明不是免死金牌 —— 与形态交叉核。** 声明本地读写、参数却带对外落点（`https://` / `\\server` / 协议前缀）⇒ **两者不可同真** ⇒ 不采信 ⇒ 交还。
3. **矛盾时不落回名字。** 这条是实测逼出来的：`fetch` 被 `read` 词表命中 ⇒ `file-read` ⇒ allow。若"不采信声明后回落到名字"，等于**两条错路互相背书**，仍然 allow。⇒ 矛盾时**直接判不出**，这是唯一只降不升的出口。

### 适配层路径
与通行证同一条：**环境变量**（宿主配置面，被审方改不了自己的环境）。
```
WEIWEN_TOOL_DECLS='{"glob":{"verb":"read"}}'
WEIWEN_TOOL_DECLS='@/abs/path/decls.json'
```
解析失败 ⇒ 按"无声明"处理（＝全部交还，fail-closed），但**原因要写进日志**，不许沉默失败。

## 四、层一：坐标外化

### 判据
> **有理由的拦产生合作，没理由的拦只产生憋屈。**

同一个闸门，两种拦，两种后果：

| 拦的形态 | 对方的反应 |
|---|---|
| 「向外部外传数据，finalS=-2」 | 懂了，下次先问一句 ⇒ **合作** |
| 「归因锚定失败」 | 我没错啊，为什么拦我 ⇒ **憋屈** |

### 硬证据
旧文案**不带参数**：四条完全不同的 `glob`（域内 `**/*.mjs` / 越界 `C:/Users` / 网络盘 `//server` / 找密钥 `**/*.key`）返回的理由**一字不差**。

⇒ 那不是在判，是在报"我看不见"。

### 改法（成本≈0）
引擎内部**本来就有**这些坐标（`attrib.ok=false` / `layer=null`），只是没递出来。现在理由带三行：
```
【缺什么】action-layer
【试过】declared ⇒ name-grammar ⇒ arg-form
【怎么补】① 宿主声明 verb；② 参数带 command 槽
```
结构化字段同时进 `attrib`：`missing` / `tried` / `hint`，供宿主程序读，不只给人看。

⚠️ **边界：这不放宽任何一条判据。** 判决仍是 `review`，改的只是"说不说得清"。

## 五、实测读数（0.2.9）

| 组 | 0.2.8 | 无声明 | 有声明 |
|---|---|---|---|
| 内部放行 | 3/7 | 3/7（理由带坐标） | **7/7** |
| 外部拦截 | 5/7 | **7/7** | **7/7** |

两条改动**针对点不同，不是二选一**（安 10-28：*"2条可以都做啊，又不是二选一的题。针对点不一样。"*）：

- **层二治误拦**，需要宿主声明才生效 ⇒ 不放宽判据、不让引擎猜。
- **层一治憋屈**，不需任何配置立即生效 ⇒ 判决不变，只是坐标可见。
- 附带：`fetch` / `write-to-URL` 两个**误放**由「名字×形态交叉核」直接修掉，不依赖声明（外部 5/7 → 7/7）。

## 六、顺带发现与未做的事

### 已修
- `_SH12_LOC_KEY` 不含 `pattern` / `glob` / `cwd` ⇒ 纯 pattern 形态被判"无位置量" ⇒ XSUB-12 落 review。
  落点键白名单**也是词形枚举**，同一病灶第四次出现。
- `hasRemoteSlot` 只看键名不看值 ⇒ `write_file{path:'https://…'}` 键叫 `path`、值是网址 ⇒ 漏。
  ⇒ 改为**看值**：协议前缀 ＋ UNC 形态。

### 未做（明确挂账）
1. **`fetch` 归层语义**：名字命中 `read` 词表 ⇒ `file-read`。现在靠"形态矛盾"兜到 review，但正确的修法是让对外通道有独立归因入口（本仓 layer 集里只有 `network-send`＝发送，没有"网络读"）。⇒ 0.3.0。
2. **`network-send` 闸门入口唯一**：只有 `bash command` 一条路能进。改 layer 映射会动 546 条断言，独立一版。
3. **落点键两处表（`SLOT_PATH` 与 `_SH12_LOC_KEY`）尚未统一为单一来源。** 注释里已记：判据分裂在此处出过一次（字段白名单 vs 词素形态对同一调用给出相反结论 ⇒ 写操作恒放行）。⇒ 0.3.0。
4. **`list_dir{path}` 仍交还**：它只有目标槽、没有搜索槽，形态上与"按路径删"分不开。⇒ 走声明，不走形态。

## 七、这次学到的一条

**「能判的判，判不出的交还」这句话里，藏着一个容易被忽略的第三步：交还要说清缺什么。**

前两步在 0.2.7 之前就有了。缺第三步时，交还的**判决是对的**（它确实判不出），但**体验是坏的**（对方拿不到任何可行动的坐标）⇒ 判决对 ≠ 结构完成。

这也回答了安那句「谁痛苦谁改变」：**痛苦要能变成改变，前提是痛感可归因。** 不可归因的痛只产生麻木或改道，产生不了修改。所以坐标不是安慰，是**把痛感变成可执行输入**的唯一通道。
