## 一、先分清楚一件事：那张截图不是我们的弹窗

安截图里的弹窗，标题是「读取文件命中询问规则，需要确认」，命中文件是 `.ssh/config` 与 `known_hosts`，选项是「允许读取 / 本次会话内始终允许 / 拒绝」——**那是宿主自己的权限询问**，不是唯稳律的。

我们的弹窗认得出：开头是「【唯稳律 · 需要你的裁决】（这是授权请求，不是通知）」，带审计对说明与冷却措辞。**今天第五次同形误读**（小D 那边四次 + 安这一次）——形状记下来了：凡弹窗先看是谁的话术，再看是谁在问。

## 二、四态怎么落（契约是封闭四值）

宿主契约 `ApprovalOutcome = 'allowed-once' | 'rejected' | 'cancelled' | 'unavailable'`，**封闭四值**，`ApprovalRequest` 无 options 字段。

| 态 | 契约值 | 行为 |
|---|---|---|
| 同意一次 | `allowed-once` | 只放行这一次，同类下次仍问 |
| 始终同意 | —— | **契约无此值**（见下） |
| 拒绝 | `rejected` | 不执行 + **同类**冷却 5 分钟（不连坐它类） |
| 待议 | `cancelled` | 不执行 + 留痕 + **不计入冷却**（人没裁决） |
| 不答 | `unavailable` | fail-closed，与静默基线一致 |

**「始终同意」的诚实实现**：契约没有对应通道，插件**拿不到人点了哪个按钮**。宿主 UI 自带「本次会话内始终允许」（截图里那个就是）——记忆记在**宿主侧**：宿主记住后不再向我们发问，我们收不到，**也不该假装收到了**。故我们只留**扩展位**：若未来 outcome 出现 `always`/`session`，即记入按裁决对象的记忆并生效；否则退化为 allowed-once，行为不变。**不伪造第五值。** 记忆可撤销：`clearReviewMemory(key?)`。

**「待议 ≠ 拒绝」**是这次的关键区分：拒绝写 `[委托人裁决]` 并起冷却；待议写 `[待议]`、**绝不带拒绝标签**、下次同类照问（人还没裁决，不能当成裁决记账）。

## 三、纪律账

- 变异两仓各 3/3 红（待议当拒绝 / 始终同意不记忆 / 同意一次变永久）。
- 弹窗正文现列五条（四态 + 不答），「始终同意」那一条明说由宿主侧接管——不把别人的能力说成自己的。
