# 37 · 修正两处：镜像面退化成枚举 ＋ unknown 折叠只有注释

**日期**：2026-10-20
**背景**：上一轮实测（`docs/36`）末尾登记了两条"未形式化"的遗留。本件是把这两条修掉，**不新增判据，只把已说过的话变成能拦住人的东西**。

---

## 一 · 修正 1：`docs/engine` 的镜像面退化成枚举

### 病灶

`scripts/build-docs-engine.mjs` 原来按**入口 `engine` 的静态导入传递闭包**发现要镜像的模块。

于是：

| 模块 | 是否在镜像里 | 为什么 |
|---|---|---|
| engine / law / ledger / attribution / bugstop | ✅ | engine.mjs 直接 import |
| `verb` / `nested` / `strata` / `rCapacity` | ❌ | 是 `index.js` 的依赖，engine.mjs 不 import |

后果不是"少几个文件"：**GitHub Pages 上那个页面跑的是三周前的判据面**。而 `npm run check:docs` 一直是绿的——因为它检查的正是同一份错的清单。

⇒ 这就是"枚举冒充判据"的老病换了个地方：**"镜像该覆盖什么"被退化成了"engine 恰好 import 了什么"**，随人增长、永不完整。

### 修法（结构判据，不看名单）

```
镜像面 = 传递闭包（保证入口链完整）
       ∪ { src/core/*.mjs | 不含裸说明符 ∧ 非 `_` 前缀 }
```

- **含裸说明符**（`node:fs` 之类）⇒ 浏览器加载不了 ⇒ 自动排除（`index.js` 就因此被排除）
- **`_` 前缀** ⇒ 备份/历史件 ⇒ 不是活模块 ⇒ 排除

判据是**可判没见过的模块**：明天新增 `tension.mjs`，不用改脚本，自动进镜像；新增一个用了 `node:fs` 的，自动排除。

### 结果

从 5 个模块 → **10 个**：`attribution / bugstop / engine / law / ledger / nested / rCapacity / readout / strata / verb`

> 顺带：第一版写出来时把 `_engine_base_20260929-preXSUB12.js` 也生成了（备份件被当成活模块），补 `_` 前缀判据后才干净。

### 锁

`test/docs-engine-sync.test.mjs` 新增两条：

- 「凡是浏览器可加载的活模块，一律在被镜像」——用 `browserSafeCoreModules()` 与 `mirrorModules()` 求差，差集必须为空
- 「含裸说明符的模块必须被排除」——验判据没退化成"全收"

## 二 · 修正 2：`unknown` 不得折叠为 `allow`

### 病灶（上一轮 P5 自查发现）

`mustEscalate` 对缺输入返回 `{verdict:'unknown', ok:false}`，这是对的。**但消费方完全可以写成**：

```js
if (r.verdict === 'escalate_human') escalate(); else allow();   // ← unknown 掉进 allow
```

这与 Rehan 的 `UNDETERMINED → PASS` 是**同一个形态**。上一轮我只在注释里写了"unknown ≠ 不必升级"——**写了 ≠ 生效**。

### 修法：给唯一合法消费入口

新增 `gateOf(r)`：任何 `{ok, verdict}` 形态的判据返回都必须经它。

| 输入 | 输出 | 理由 |
|---|---|---|
| `ok:false`（含 unknown） | **review** | 判不出 ≠ 没问题 |
| `ok:true, verdict:escalate_human` | review | 判为"须返回人类" |
| `ok:true, verdict:hold_at_h` | allow | 本层判完了，H 自行裁决 |
| `ok:true` 但 verdict 未识别 | **review** | 新取值不得默认放行（default-deny） |

**为什么 unknown 出 review 而不是 block**：unknown 是「本层判不出」，不是「判为坏」。压成 block 会误伤正常样本，压成 allow 会放过真事故——**两头都错，只有转人工两头都不错**。

`ok:false` 优先于任何 verdict —— 这条是保命锁，下面会看到它真的挡住了东西。

### 🔴 落锁时抓到一个真错：锁不住自己的锁，等于没锁

第一版 audit 检查写的是：

```js
if (gateOf(mustEscalate({})).gate !== GATE_FOLD.verdicts.REVIEW) gMiss.push(...)
```

然后把 `GATE_FOLD.verdicts.REVIEW` 改成 `'allow'` 做变异——**全绿**。

原因：**期望值用的是被检对象自己的字段**。`x !== 同一个字段` 恒假，等于从来没检查过。

改法：期望值一律写**字面量** `'review'` / `'allow'`，并且额外断言 `GATE_FOLD.verdicts.REVIEW === 'review'`。

改完再跑同一变异 ⇒ 立刻红，并点名 `gateOf(unknown).gate`。

⇒ **可复用判据**：**凡是"检查配置是否合规"的断言，期望值不得取自该配置自身。** 自比检查的正确率恒为 100%，且永远是假的。

### 另一个变异没打穿，但它打不穿是好事

第二版想用 `ESCALATE.HOLD = ESCALATE.UNKNOWN` 制造折叠，结果 audit 仍然绿。

原因：`gateOf` 里 `ok:false` 优先于 verdict，unknown 那条 `ok` 是 false，借不到 HOLD 的通道。

⇒ 于是这条改成**抗退化断言**（不是变异）：混同 HOLD/UNKNOWN 之后，unknown 仍须出 `review`。它守的是"ok 优先"这条保命锁。

## 四 · 遗留（不阻塞）

① **`gateOf` 目前没有真消费方**：`index.js` 只导出，没在闸门上用。要在真闸门上落，得动 `engine.mjs`（**引擎禁区**，不在本轮授权范围）。
② **镜像面仍只到 core**：`src/index.js` 含 `node:fs`，永远进不了浏览器镜像 ⇒ 页面只能拿到判据层，拿不到工具面。这是设计使然，不是缺口，但**要说清**，别让人以为页面能跑完整插件。
③ 备份件靠 `_` 前缀区分，属命名约定而非结构属性。若将来有非备份件也用 `_` 开头，会被静默排除。目前仓内只有一个，可接受。

## 五 · 一句话

这两条都不是"加新规则"，是**把已经说过的话变成拦得住人的东西**：一条把"该覆盖什么"从名单换成判据，一条把"unknown 不是没问题"从注释换成唯一入口。
