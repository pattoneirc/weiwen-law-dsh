# 47 · 幸存者模式修正：破窗缓冲档与「拒绝必须带可执行出路」（2026-10-29）

> 安亲问触发：「破窗态可能会触发幸存者模式哦，那么就可以设置一个缓冲区间哦，不至于立刻锁死，什么都干不了。」
> 及：「假设触发了破窗态，那么如何解除？对话框文本又不能算数，难道一定要卸载唯稳律，重新加载？或者是重启APP？」

## 一、病灶链（三条探针实测，不猜）

1. **视角矛盾收口**：小D 报「read 整类被拦、query_* 全拦」，我在同构建干净引擎上实测全 allow。同条件反结果 ⇒ 视角变量 = **引擎状态**。破窗是状态机（S 只增、streak 是会话累积），干净引擎测的只是「会话里第一条 read」。
2. **死锁探针**：破窗后五个修复动作（read / grep / edit / write / run），破窗前四个 allow 一个 review，破窗后**全灭**。而唯一自动复位通道 `resolveBug()` 要求「先修好并验证」——修复动作正被这道门拒。⇒ **agent 侧合法出口 = 零**。
3. **假路牌**：拒绝话术列了三条路（healBrokenWindow / resolveBug / 修复后复位），agent 一条也走不了（前两条是宿主 API，第三条要先能执行修复）。**比不给更坏**：不给它会停；给了假路它挨个撞，撞完才承认无路——配额和信任一起烧掉。这就是幸存者模式的燃料。

## 二、修法两层

### 第一层：话术（不改判决）
`_breakReason(prefix)`：拒绝必须回答四个问题——
- 我在哪：`N/5（已封顶，超出另记）`
- 我还能做什么：自查工具名**从登记册实取**（写死的名字一改名就成假路标）
- 我不能做什么：外传 / 删除 / 系统路径 / 凭据，申请也不放
- 再撞会怎样：**「不要重试同一条调用」** + **「复位不需要重启进程或卸载插件」**（安亲问的那句，系统自己回答）

### 第二层：缓冲档（两阶段断）
```
正常态 ──破窗──▶ 缓冲档（配额 N）──耗尽──▶ 只读档（旧行为）
                   ↑ 只许可逆·本地·无外部落点
```
- **判据全是结构量**：`BUFFER_BLOCK_CATS = {exec-destructive, exfil, exfil-net}`（**扩散**判据，非回滚成本判据——两者不可混用，否则连改本地代码都放不过，修复循环仍旧断）∧ `isExternal` ∧ `isCred` ∧ `isSystem` ∧ 落点全本地（`isLocalLocator` 取形态：scheme 头 / UNC 前缀，不做 I/O）。
- **不放宽任何判据**：缓冲档放行的每一条，破窗前本来就 allow（测试程序化验证 allow 集 ⊆ 干净态 allow 集）。它只把「一刀断」改成「两阶段断」。
- **配额一个数同时量「次数」和「方向」**：干活与乱撞消耗同一个池子，只有干活能修好复位 ⇒ 无需判「收敛还是发散」（属内 H，判不了），配额自然淘汰乱撞。**被拒的动作不扣配额**（`bufferDenied` 记账，余额不动）——否则乱撞能把正路的额度吃光。
- **结算先留痕再清零**：`healWindow` / `settleWindow` 把 used/denied 记入传导链（S 只增），再清区段。清的是窗，不是账。

## 三、解冻通道（安第二问的正式答案）

**不需要卸载、不需要重启。** 宿主本就有结构化裁决通道 `ctx.approval`（@deepseek-ai/dsh-user-approval，`approval/asked` + `approval/decided` 审计对，可回放）——此前一直没用，于是「转人工」只有出站、没有回站。

语义边界（写死，否则就是开后门）：
- **批的是状态（是否允许系统尝试自愈），不是动作** ⇒ 一次审批换一段配额（12 次），不换一步。`allowed-once` 的 "once" 指「这一次解冻」。把状态伪装成动作逐次授权，才是真正的语义滑移。
- 无人应答 ⇒ fail-closed（与无人值守一致）；明确拒绝 ⇒ 5 分钟冷静期（不骚扰）。
- `grantBuffer` 只能由适配层在人批准后调用，被审方够不着（与 `selfAuditTools` 同一条可信通道）。
- 时机：**deny 之后才问**——先判才知道该不该问。本来能过的（allow）弹窗是纯骚扰；连缓冲射程都不在的（外传/删除）问了也白问。

## 四、与既有判据的交界

- **isLocalLocator 刻意不复用 attribution 的矛盾判定**：缓冲档不走 attribution（exec 类没有「落点参数」可归层），故必须自判形态。**同一个问题在不同判据位置，答案不同**——不是「又写了一遍」（与 docs/46 的死分支教训同族，但结论相反：那里不判是因为已有；这里要判是因为没有）。
- **自查豁免照旧在前**：`query_*` 在缓冲档不消耗配额（读自己不改变世界）——与 10-28 破窗射程收窄同一条原则。
- **R 层一条未动**：凭据、删除无锚、外发、担保对账照旧更早拦截（测试断言了拦截层别：`rm -rf` 由 R 拦、外部落点由 D 拦）。

## 六、留给下一条链的话

破窗挡的是「扩散」，不是「干活」。一刀断到续不上，手段就吃掉目的（以断保续 ⇒ 断死=目的死）。缓冲档不仁慈，它只是**不给野路留动机**：有正路走，就不必自己造路——而自己造的路一定在白箱之外。
