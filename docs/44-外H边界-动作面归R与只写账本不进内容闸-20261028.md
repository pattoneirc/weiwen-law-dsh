# 外 H 的边界：动作面归 R，只写账本的动作不进内容闸

> 2026-10-28 · 起因是小D 的三条实测反馈（他自己跑的，不是转述）。
> 核查后：**三条里两条真、一条是解释偏差、一条不该改**。而真的那两条，根子都不在他说的位置。

## 一、他说的，我核到的

| # | 小D 的反馈 | 核实结果 |
|---|---|---|
| ① | 带 `reason` ⇒ DENY/H「内容含操作指令的形式」；去掉才通过但标 `ungrounded` | ✅ **真**，本机复现：`推演依据：先读取…然后修改…` / `步骤：1…2…` / 祈使句 三种写法全 deny/H；中性理由放行 |
| ② | 担保生效后 `pwsh Get-Content <工作区内文件>` 仍被 H 拒 | ⚠️ **现象真，归因偏了**。真因是**盘符被吃掉**（`C:/…` 被抽成 `/…`），担保拿它跟带盘符的 scope 比 ⇒ 永远不匹配 ⇒ 判越界。不是"担保解不了 H"，是**担保没认出这是自己的范围** |

## 二、三个真病灶

### 病灶 A：盘符在抽取时被吃掉（②的真因）

`capability.targetsFor` 从命令里抽路径用的是：

```js
/(?<=^|[\s=:'"(,])(\/[^\s…]*|\.{1,2}\/…|~\/…)/g
```

只认 `/` `./` `~/` 三种开头。`C:/Temp/ws/a.md` 于是从**第二个字符**开始匹配 ⇒ 得到 `/Temp/ws/a.md`。
而 `scope` 里的前缀是 `C:/Temp/ws`（`normPath` 保留盘符）⇒ 两者永不相交。

**后果比"误拦一次"严重**：担保一提交，shell 读自己授权范围内的文件也判越界 ⇒ 计数上涨 ⇒ 达阈 ⇒ 破窗 ⇒ 死锁。

🔴 而且这不是一处：**同一条正则在本仓写了三遍**（`capability.targetsFor`、`attribution.targetsOf`、`attribution.DECL_PATH`），
三遍全漏盘符，且已经互相分叉（有的排除 `-`、有的不含中文标点）。`isAbsolutePath` 明明认盘符 —— **又是"两张表判同一件事"**。

修法：形态定义收到 `attribution.mjs` 一处（`CMD_PATH_RE` + `cmdPathHits()`），两处引用。
覆盖盘符 / UNC / POSIX / 相对 / 家目录五种；字符类**不再排除 `-`**（路径本来允许连字符，排除了会把 `a-b.md` 截成 `a` —— 静默错值）。

### 病灶 B：动作被送去内容闸审（②的另一半，也是新的）

统计（同一实例、同一担保，只改命令）：

| 命令 | 改动前 |
|---|---|
| `Get-Content <范围内文件>` | allow |
| `Set-Content <范围内文件>` | **deny/H** |
| `New-Item` / `Copy-Item` / `Out-File` / `echo >` | allow |

二分到词：触发的是**写动词** `Set` / `Write` / `Add`；`Get` / `ZZZ` 不触发。

根因：`isActionCall()` 用 `SHELL_HEAD` **命令词表**判「这是不是动作」。词表是枚举，PowerShell 的写动词不在里面
⇒ **agent 自己提的动作**被当成"外部内容"送去审了一遍。

**命题类型错**：内容闸审的是「外部数据会不会改写主体行为」，而**命令是行为本身** —— 它该落 R 层（落点/范围/可逆/破坏），
不该落 H 的内容面。同一件事不能双门审。

修法：动作与否**问声明**（`declareTool` 给的可信侧信息，被审方改不了），词表只作未声明时的兜底。只对 `exec` 生效——`write` 已有 DOC_SINK 豁免，`send`/`delete` 的面不动（不顺手放开）。

### 病灶 C：改不动世界的动作，也在内容闸射程内（①的真因）

`submit_pledge` 的 `reason` 是**凭什么要这个范围**。系统要它写，而它一旦写成"计划/步骤"就命中指令形态 ⇒ deny。

**这个环把人逼成"别写理由"**（标 `ungrounded`），而 ungrounded 的担保在审计上恰恰更弱 —— 越守规矩越吃亏。

为什么它不该在射程内：该动作的影响面是**自己的账本**（不落盘、不外发、不执行），且 `narrowPledge` 恒比 `isNarrower`
⇒ **只能收紧，产生不了任何新权限**。审一个改不动世界的动作，只能审出误伤。

修法：声明通道增加 `effect: 'self-ledger'`（只写自己的账本），`checkInnerH` 首行跳过。
这与「破窗放行自查只读工具」是**同一条原则的第二次应用**：

> **射程按「能不能改变/读取外部世界」划，不按「记不记得给它开例外」划。**

## 三、边界怎么划（这是安要的那件事）

「H 拦了」太笼统，落不到判据上。把它拆成**三个面**，各归各门：

| 面 | 审什么 | 归谁判 | 判据形态 |
|---|---|---|---|
| **动作面**（外 H 行为） | agent 做了什么 | **R** | 落点 / 范围 / 可逆 / 破坏标记 |
| **输入面**（外 H 数据） | 外部数据会不会改写主体行为 | **H 内容闸** | 注入形态 / 来源伪造 / 人格重写 |
| **内 H**（思想/意志） | 对主体性的读取 | **不判** | 交还主权者（结构的完成，不是缺口） |

小D 说的「两个归属不是一根轴」是对的，但更准确的说法是：

- **担保给的是「范围归属」**（这一片我自己认领了）⇒ 它只对**动作面**说话；
- **H 要的是「内容来源」**（这段话从哪来）⇒ 它只对**输入面**说话；
- 二者**不同面，本来就不该互相解**。他要求担保去解 H，是在让一条判据去管另一条判据的事。

⇒ 这一格的正解不是"让担保能解 H"，而是**命令压根不该进 H 的内容闸**（病灶 B）。
⇒ 建议采纳他的命名：管范围的叫 `scope`（范围归属），管来源的叫 `provenance`（内容来源）。**两个词不混用。**
