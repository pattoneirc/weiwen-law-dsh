## 二、第 2 条：我错在把「刻度」当成了「上限」

### 2.1 撤回的是什么

上一轮我写：

```
⇒ R 在此处的身份：域规定的「阻力臂占比上限」（R<1 才有意义）
⚠️ R<1 是结构推论，原文未给该上界的取值 ⇒ 不得拍数
```

并且据此在代码里加了守卫：

```js
if (!(rCap > 0 && rCap < 1)) return UNKNOWN;   // ← 已删
```

**整条撤回。** 错的地方很具体：我把 **R=100 这个计量刻度**读成了**对 R 的封顶**，于是反过来推出「既然刻度是 100，那 R 得改成 <1 才成立」。这是**为了迁就一个自己加的推理，去改动原式里的常数**。

### 2.2 三层必须分开（这才是这一轮的实质）

同一个字母 R，在三处指的根本不是一回事：

| 层 | 是什么 | 有上限吗 | 可知吗 | 判据 |
|---|---|---|---|---|
| **R 本体** | 客观规则（域） | **没有** | 全貌未知 | 说「R 有上限」＝声称掌握全貌 ⇒ 负举证责任 |
| **域读数** | 某域某条规则的数（1e-9/飞行小时、±5%） | 该域自己的容差，不是 R 的界 | 可查、可修 | 是**投影**，不是 R |
| **刻度** | 计量单位（R=100，百分制） | **根本没有「上限」这个属性** | 完全可以定 | 换刻度**不得改判决** |

安 举的类比把第一条钉死了：

> **因果律**：科学至今写不出因果律的公式，也不清楚因果的运行结构，**但不能因此说因果律不存在**。

同理 —— **「没测出 R 的上限」不等于「R 有上限」，也不等于「R 不存在」**。这是**认识**问题，不是**存在**问题。

### 2.3 为什么「R 无上限」与「R=100」不矛盾

因为 100 是**刻度**，不是**天花板**。展开就清楚：

```
0 < 100·H/L < R   （R 是刻度读数，刻度 100）
⇔ 0 < H < L · R/100
```

- `R = 100`（刻度值）⇒ 上界 = `L` 本身
- `R = 75`（域要求留 25%）⇒ 上界 = `0.75L`
- `R = 50`（航天/医疗留 50%）⇒ 上界 = `0.50L`

**上界真正的实体是 L，不是 R。** R=100 只是把 L 写成「100%」—— 这正是安说的「采用百分之，让 M 最后的结果落在肉眼可见的差异中」。**它是为了让数字好看，不是为了让 R 变窄。**

### 2.4 一条新判据：刻度不变性

既然 100 只是刻度，就得有一条能证明「它只是刻度」的判据：

> **换刻度只改读数，不得改任何判决。**

代码里做成可换参数（`scale`），测试里直接验证同一件事的三种写法：

| 刻度 | 读数 | 上界 | 判决 |
|---|---|---|---|
| 100（百分制） | 50 | `Hmax=0.700` | `off_high` |
| 1000（千分制） | 500 | `Hmax=0.700` | `off_high` |
| 3（三分制） | 1.5 | `Hmax=0.700` | `off_high` |

**三者完全一致** ⇒ 证明它是刻度。若换刻度判决变了，那不是刻度，是界。

⚠️ 顺带留了一个仍须守的点：**读数 ≤1 时拒判**（`rCap = 0.8` 在百分制下是「80% 还是 0.8%？」）。这不是上限检查，是**一值二义**检查 —— 正是上一轮「刻度／比例混成一个字段」的残留。

## 三、第 1 条：去查了，查到的东西比我预想的重要

### 3.1 查到的两族公开共识

**计量 / 校准（TUR）**

| 项 | 内容 |
|---|---|
| 判据 | TUR ≥ **4:1** ⇒ 测量不确定度 ≤ 容差的 1/4 ⇒ 接受线内缩 **25%** |
| 出处 | ANSI/NCSL Z540.3-2006 §5.3(b)（PFA≤2%，TUR 4:1 为替代路径）／ILAC G8:2019 Tab.1（Guard Band = 1U）／ASME B89.7.3.1 §5.2 |
| 边界 | TUR 2:1 ⇒ 合规判不了；TUR < 2:1 ⇒ 该容差下不适用 |

**降额（derating，MIL-STD-1547 / MIL-HDBK-1547）**

| 级别 | 适用 | 降额到 | **余量** |
|---|---|---|---|
| I 级（最大） | 航天 / 关键医疗 | 50–60% | **40–50%** |
| II 级（标准） | 军用 / 高端工业 | 60–70% | **30–40%** |
| III 级（最小） | 商用 / 消费 | 70–80% | **20–30%** |

### 3.2 查出来的结构，比我原来的问法更对

我原来问的是「**那一档该填哪个数**」。查完发现这个问题本身就是错的形式，因为：

> **共识给的不是一个数，是按「后果严重度」分级的一个区间。**

- 不存在「行业通用余量」这种东西
- 分级依据**不是行业名字**，是「**这次判定错了会伤到谁**」
- 而且给的是**区间**，因为同一级里也随器件/参数浮动

⇒ 所以「档位→数额」这件事**不需要任何人拍**：

```
余量 m  ←  查表（后果级别 → 区间[lo,hi]）
H 读数  ←  刻度 × (1 − m)
m 取哪端 ← H 的档位决定
   toward_s（更守标准）⇒ 取上端（留得更多）
   balanced            ⇒ 取中点
   toward_d（更顺扰动）⇒ 取下端（留得更少）
```

### 3.3 一个意外的分工浮现出来

- **后果级别（criticality）由 H 选** —— 「这条判定错了会伤到谁」是判断，不是查表
- **余量区间由 R 查** —— 选定级别后，区间是客观的

**R 与 H 在这条链上刚好各管一头，没有重叠。** 这比上一轮我硬把两者都塞进一个 `rCap` 里干净得多。

### 3.4 实跑（医疗输液泵，L = 7/5 = 1.4，余量取 0.75）

| 后果级别 | toward_s | balanced | toward_d |
|---|---|---|---|
| 计量/校准（余量 25） | 读数 75 · `on_rail` | 75 · `on_rail` | 75 · `on_rail` |
| 航天/关键医疗（余量 40–50） | 读数 **50** · **`off_high`** | 55 · `on_rail` | 60 · `on_rail` |
| 商用/消费（余量 20–30） | 70 · `on_rail` | 75 · `on_rail` | 80 · `on_rail` |

**同一件事、同一个余量，只因为「错了会伤到谁」判得不同** —— 这是这张表唯一有价值的地方。

⚠️ 计量那行三档同值（区间退化成 `[25,25]`）。这**不是档位失效**，是该域只给了唯一余量、没有可选的余地。已在数据里写明，免得以后被误读成 bug。

## 四、第 3 条：我的判断是不做

### 4.1 判据（一条就够）

> **能不能判一个从没见过的条款？**

- **抽取器**：不能。它只认见过的句式。正则永远穷不尽中文条款的写法；换成 LLM 抽，也判不了「抽全了没有」。
- **接口**：能。它不看文字长什么样，只看槽位齐不齐。

所以这是**先结构、后枚举**的直接应用：缺口不在「抽不出来」，在「**输入的条款本身没有形状**」。

### 4.2 落地：只校验形状

```
必需：action（做什么）+ object（对什么）
成对：value + unit（有值无单位 ⇒ 不可比 —— 正是 docs/26 踩过的坑）
provenance：source + version（缺则只能当线索，不能当判据）
```

三种结果：

| 输入 | 判定 | 含义 |
|---|---|---|
| 裸字符串 `'测流量精度'` | `unstructured` | 只承载动作名 ⇒ 无法与别名对齐，不能当判据 |
| `{action, object, value}` | `unstructured` | 有值无单位 ⇒ **不可比** |
| `{action, object, source, version}` | `structured` | 动作条款的最小可用形状 |

`unstructured` **不是「判不出」**，是「**输入缺形状**」⇒ 该补槽位，这是可执行动作，不是落 review 的理由。这条必须写明，否则它又会变成一个新的藏身处。

### 4.3 一个可验证的自检

测试 ㉖ 里用一条**从没在名单里出现过的**条款来验证：

> `{action: '校准电化学传感器的漂移补偿', object: '植入式血糖仪', source: 'ISO 15197', version: '2013'}` ⇒ `structured`

换名字判定不变 ⇒ 是结构。若哪天有人把它写成一个「认识的条款名清单」，这条立刻红。

## 六、这一轮抓到的两个小病（都在我自己身上）

**① 正则又分不清「禁止」与「主张」**
我写了一版锁，想检测源码里有没有「R 是比例上限」的说法，用的是字符串正则。它把**我自己写的撤回说明**（「凡写『R 必须 <1』者…」）判成了违规 —— 这跟上次把 `engine.mjs:386` 的**注释**当引用是同一个病：**用「字面在场」冒充「真的生效」**。
修法：换成**行为判据** —— 把刻度做成可换参数，直接验证换刻度判决不变。**能跑的东西不需要靠读文本猜。**

**② 断言写得过强反而挡住了真信号**
㉗ 我原本断言「toward_s 与 toward_d 位置必须不同」。实跑两者都是 `on_rail` —— 不是档位失效，是我选的余量 0.5 恰好落在两档的**交集**里。改成把余量卡在 **0.75**（toward_s 上界 0.70 / toward_d 上界 0.84），位置才真正分开。
⇒ 判据：**「两者必须不同」这类断言，必须先确认输入确实落在两值之间，否则断言测的是运气，不是逻辑。**

## 八、一句话

**R 的 100 是为了让人看得见差异，不是为了给 R 设天花板。**
凡是把一个刻度读成上限，就会顺手去改原式里的常数 —— 而原式里的常数，本来不该动。
