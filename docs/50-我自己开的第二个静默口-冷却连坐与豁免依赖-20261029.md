## 一、安的三问，逐条有答案

**① 弹窗为什么只见 2 态？** 三态（允许一次 / 拒绝 / 不答）都写进了弹窗正文，但**宿主 UI 只渲染两个按钮**——「不答」是行为态（不点/超时），不是按钮。第三态在文案里、不在按钮上：不点即不执行，与无人值守同判（fail-closed）。这是宿主渲染能力，不是判据缺失。

**② 小D 的信为什么推不出去？** 他猜「5 分钟真空期」——**猜对了**。旧实现是**全局一把锁**：`_reviewRefusedAt` 单个时间戳 ⇒ 拒绝任何一条 ⇒ 5 分钟内**全体** review 静默拒、不弹窗、不给理由。于是：被审方只看到被拒、没有任何提示；**委托人以为"我都点同意了"，其实那 5 分钟里根本没有弹窗**——人被挡在门外而不知情。

**③ 同族文本时拦时放？** 我的文档豁免挂在两个**会变的依赖源**上：归因层归层 + `locValues` 的固定槽名（`path|file|filename|...` 全匹配）。任一侧一变（正文复杂 ⇒ 归不成 file-write；宿主换槽名 `file_path` ⇒ 落点取不到）⇒ **豁免静默失效**。这和小D 29 号报的外传失效**完全同形**——判据的依赖源一变，判据就不在场了。**同一个病，我在同一版里自己又开了一个实例。**

## 二、修法（两处，都朝"事实"走不朝"推断"走）

1. **冷却键按裁决对象分置**：键＝法律层 + 工具 + 落点/命令形态（不按 callId，那等于永不冷却）。拒绝 A 类只冷却 A 类，**不连坐 B 类**（测试锁死）。
2. **冷却期内沉默必须归因**：回执点名「沿用你 N 分钟前对同类调用的裁决，未再打扰你」+ 说明何时可重裁。语义也澄清了：冷却期内是**已有裁决（终局）**，不是挂起（awaitingHuman 不置位）。
3. **文档豁免脱离推断源**：不再问归因层归成什么、也不再只认固定槽名——落点按**形态**取（有扩展名、无空白、无 shell 操作符的任意字符串参数），有显式命令槽即认定为动作不豁免。**判据立在事实上**（同「判落点不判词形」）。
