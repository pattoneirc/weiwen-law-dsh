# 48 · 弹窗（review 出口）：判得出「不确定」，出口不再被压掉 —— 该静默的仍静默

> 阿清（电脑端）｜2026-10-29｜两仓落码 · 安拍板「要要要」｜读数：CN 633/633 · EN 640/640 · 变异 5/5 两仓全红

## 一、缺口是怎么实锤的

小D 27 实测：0.2.14 上 review（中风险/判不出）是**静默拒**，没弹窗——他判「这是缺口，不是已完成项」。核适配层：引擎判得出「不确定」（`review` 判决），但 `src/index.js` 压平分支的注释自己写着：

> 对外语义固定为 deny：宿主契约只认 deny / next()，返回 'review' 有被当未知类型放行的风险。

**缺口在接法层，不在判据层**：判决存在，出口被压掉。这正是「写了 ≠ 生效」的又一例——判据在场 ≠ 出口在场。

安拍板的由来也记一笔：小D 第一次实测时看到的唯一弹窗是 DSH 沙箱的（`file access denied under workspace-write`），安以为是唯稳律的，「激动得差点蹦起来」——结果是别人家的。这一票「要要要」里有一半是「我们要有自己的那个弹窗」。

## 二、修法：review ⇒ approval 通道请求人类裁决

`requestReviewVerdict`（适配层）+ pre-execute review 分支。与缓冲档的审批**正交**：

| | 缓冲档解冻（B10） | review 弹窗（本件） |
|---|---|---|
| 批的对象 | **状态**（解冻一段 12 步配额） | **动作**（放行这一次调用） |
| once 的含义 | 这一次解冻 | 这一次调用——下一次同 call 重新走瀑布重新问 |
| 触发 | deny(D) ∧ 余额 0 | kind='review' ∧ 非破窗态 |

**弹窗带三样**（小D 27 §四，沙箱好形态照抄，粒度不抄）：谁拒的（law）、为什么（reason 原文）、你能做的那一步（允许/拒绝/不答＋粒度明示「只放行这一次调用」）＋审计对说明（不是聊天说一句就算数）。

**三态映射**（安的：同意/不同意/再议）：

| 安的三态 | approval 现状 | 落法 |
|---|---|---|
| 同意 | `allowed-once` | 放行这一步（不进 markBlocked：回执是真结果） |
| 不同意 | `rejected` | 终局 deny，标注 `[委托人裁决]`，**不再挂 awaitingHuman** |
| 再议 | **无对应态** | 不假装审批契约有挂起态 ⇒ 落为：本轮不执行＋runtime.log 留痕＋人回头翻（aqing/135 §二 方案 b） |

## 三、该静默的仍静默（对照组，测试锁死四条）

1. **确定性 deny 永不弹**（R 层凭据读等）——弹窗只服务「判不出」，不给「判了但拒」翻案；
2. **真破窗态不弹**（R 投影累积置 `windowBroken=true`）——止损 fail-closed，不得被弹窗旁路；该态下 review 走压平，与 0.2.14 逐位一致；
3. **无 approval 服务 / 无 agent 上下文 ⇒ 静默**（向后兼容：没有审批面的宿主零回归）；
4. **审批异常 ⇒ fail-closed**；刚被拒过 ⇒ 冷却期不骚扰。

## 四、一个值得留痕的结构事实（probe 实测，防将来误修）

`windowBroken=true` **只由 R 投影累积路径设置**（engine L2391）；`onFailure` 只加 `failureStreak`、不设旗标。

⇒ 「streak 超阈但未正式破窗」（onFailure 路径）时缓冲档在效、`windowBroken=false`，review 弹窗**会出现**——这是**设计意图不是漏**：review ＝ 判不出交人类，弹窗正是接通回站。测试文件头部写明了这条，变异 M1 锁住「真破窗态不弹」的半边。
